# Mimi shell (`MIMI.exe`)

The native Windows app for Mimi: a thin, full-screen window around **Microsoft Edge WebView2**
that shows the web UI served by Mimi Core on `http://127.0.0.1:7600/`. It starts Core when needed,
shows a boot screen while Core wakes up, and gives the UI a small bridge to the host (full screen,
tray, quit, open folders).

It is deliberately small and toolchain-free: one C# 5 file compiled by the C# compiler that ships
inside .NET Framework 4.8 on every Windows 10/11 PC. No Visual Studio, no .NET SDK, no Rust/Tauri,
no admin rights.

| File | What it is |
| --- | --- |
| `MimiShell.cs` | The whole app (WinForms + WebView2), C# 5. |
| `splash.html` | Boot and error screen, embedded into the exe and shown with `NavigateToString`. |
| `app.manifest` | Per-Monitor V2 DPI awareness, Windows 10/11 compatibility, `asInvoker`. |
| `mimi.ico` | App icon, 16-256 px (generated by `make_icon.ps1`). |
| `make_icon.ps1` | Draws `mimi.ico` with System.Drawing: the "Well" orb in a navy tile. |
| `build.ps1` | Reproducible build (below). |

## Build

```powershell
powershell -ExecutionPolicy Bypass -File shell\build.ps1              # latest stable WebView2 SDK
powershell -ExecutionPolicy Bypass -File shell\build.ps1 -Offline     # use the cached SDK only
powershell -ExecutionPolicy Bypass -File shell\build.ps1 -WebView2Version 1.0.4191.47
```

`build.ps1` (PowerShell 5.1, all paths relative to its own location):

1. Resolves the latest stable `Microsoft.Web.WebView2` package from nuget.org (or the pinned
   version), downloads the `.nupkg` into `.tools\webview2sdk\` and unzips it to
   `.tools\webview2sdk\<version>\`. Cached; without network it falls back to the newest cached SDK.
2. Copies `Microsoft.Web.WebView2.Core.dll`, `Microsoft.Web.WebView2.WinForms.dll`
   (`lib\net462`) and `WebView2Loader.dll` (`runtimes\win-x64\native`) into the Mimi root.
3. Checks that `MimiShell.cs` and `splash.html` are pure ASCII (see *Text encoding*), then compiles
   with `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`
   (`/target:winexe /platform:x64 /optimize+ /codepage:65001`, icon, manifest, `mimi.ico` and
   `splash.html` as embedded resources) into a temp folder and only then copies `MIMI.exe` into the
   root, so a failed build never leaves a broken exe. Any compiler error fails the build.

A running `MIMI.exe` locks the exe and DLLs: quit Mimi before rebuilding (the script says so).
Build outputs (`/MIMI.exe`, `/*.dll`) and `.tools/` are git-ignored.

To regenerate the icon: `powershell -ExecutionPolicy Bypass -File shell\make_icon.ps1`
(optionally `-PreviewPng sheet.png` for a contact sheet of all sizes).

## Run

```
MIMI.exe              borderless full screen on the current monitor (taskbar covered)
MIMI.exe --windowed   normal resizable window, 1280x800 (device-independent px), centred, dark title bar
MIMI.exe --startup    for sign-in autostart: same, but never forces itself to the front
MIMI.exe --dev        DevTools (F12), F5 reload, browser accelerator keys, full context menu
```

The Mimi root is always the folder containing `MIMI.exe`; nothing is hard-coded, so a Mimi folder
can live on any drive or a USB stick.

## What happens at start-up

1. **Single instance.** A named mutex (`Local\MIMI.Shell.SingleInstance`) keeps one shell per
   session. A second launch signals the running one through a named event
   (`Local\MIMI.Shell.Activate`), passes it the right to take the foreground, and exits; the
   running window shows and focuses itself.
2. **Core.** If nothing listens on port 7600, the shell starts
   `python\pythonw.exe -m mimi serve` in `core\` with `MIMI_HOME=<root>`, hidden. This happens as
   the window opens, in parallel with WebView2 start-up. Core's output is not redirected (Core logs
   to its own files).
3. **Boot screen.** The window appears at once on `#060A12`. The WebView2 control stays hidden
   until its first page has loaded (its initial `about:blank` would paint Chromium's grey), so
   there is never a white or grey flash. Then `splash.html` fades in: the glowing "Well" orb, the
   Mimi wordmark and a status line the shell updates with `ExecuteScriptAsync`
   ("Waking up...", "Starting Mimi Core...", ...). If Core is already running, the UI usually
   answers before the splash has even loaded and Mimi opens straight into the UI; once the splash
   is on screen it stays for at least 1.1 s and fades out, so it never just flickers.
4. **Waiting for Core.** `GET /api/ping` every 250 ms until it returns `{"ok": true}`. A refused
   connection to localhost takes about 2 s to fail on Windows (TCP SYN retries), so pings overlap
   instead of running back to back, and the TCP listener table is used to see instantly whether
   anything listens at all. No proxy is ever used for localhost.
5. **Success:** the boot screen fades out and the window navigates to `http://127.0.0.1:7600/`.
   **Failure** (no answer after 90 s, Core exited, Python or `core\` missing, port taken by
   something else, UI page failing to load) turns the same page into a friendly error screen with
   **Retry**, **Open logs folder** and **Quit**. The buttons are touch-sized and work with the
   keyboard (arrows, Enter) and the built-in controller (D-pad/stick, A). Retry restarts Core if
   it died.

## Window, keys, tray

- **F11** or **Alt+Enter** toggles full screen (borderless, exactly the monitor's bounds, which
  Windows treats as full screen and hides the taskbar behind). A page element entering HTML
  full screen (`requestFullscreen()`) takes the window with it.
- **Ctrl+Alt+M** (global hotkey) shows Mimi, or hides it to the tray when it is in front.
- **Tray icon**: *Show Mimi*, *Full screen* (checked when on), *Quit Mimi*; click or double-click
  shows the window. The menu is dark and has roomy, touch-friendly rows.
- **Alt+F4** / the close button **quits** (it does not minimise).
- Hiding to the tray lowers WebView2's memory target; the page sees `document.hidden`, so timers
  may be throttled while hidden.

## Quitting

The window hides at once, then: if **this shell started Core**, that process is still running and
it is the process that owns port 7600 (checked in the TCP table), the shell sends
`POST /api/system/shutdown` (2 s timeout). If Core doesn't accept - it is still booting, hung, or
lacks the endpoint - it gets up to 3 s to exit on its own (0.5 s if it isn't even listening yet)
and is then ended, so it can never linger holding gigabytes of RAM. Core keeps its child servers in
a kill-on-close job object, so they go with it. A Core the shell didn't start (for example one
started by hand from a console) is never touched, even if the shell's own Core lost the race for
the port. The single-instance lock is released as quitting begins; a new launch in that moment waits
for the old shell to finish instead of being swallowed. When Windows signs out, the same happens
synchronously within 2.5 s.

## WebView2 configuration

- User data folder: `<root>\data\webview`. Crash dumps stay local (`IsCustomCrashReportingEnabled`),
  no SmartScreen/reputation lookups, tracking prevention off (nothing to block offline), Fluent
  overlay scrollbars, autoplay allowed without a click (`--autoplay-policy=no-user-gesture-required`)
  so Mimi can speak as soon as an answer is ready.
- Browser chrome off: no status bar, zoom, pinch-zoom, swipe navigation, autofill, password saving,
  built-in error pages or browser accelerator keys (Ctrl+P, Ctrl+F, F5, ...). Editing keys
  (Ctrl+C/V/X/A/Z) work as usual. `--dev` turns DevTools, accelerators and the full menu back on.
- Context menu: none on plain UI; text fields and selected text keep the editing entries (cut,
  copy, paste, select all, undo/redo, emoji, spelling). Everything else (Back, Reload, Save as,
  Print, Inspect) is removed outside `--dev`.
- Permissions requested by the Core origin (`http://127.0.0.1:7600`, or `localhost:7600`) are
  granted without a prompt: microphone, camera, geolocation, clipboard read, notifications,
  autoplay, persistent storage. Other origins are denied; rarer permissions from the Core origin
  get WebView2's normal prompt.
- Navigation: only the Core origin (plus the shell's own boot screen) is shown inside Mimi.
  External `http(s)` links open in the default browser, and only when the user clicked them.
  Pop-ups (`target="_blank"`, `window.open`) never open a WebView2 window: they also go to the
  default browser, local links included, so the app keeps its state. Use normal navigation for
  in-app pages. Other schemes (`file:`, custom protocols) are blocked.
- The user agent gets a ` MIMIShell/0.1.0` suffix, handy in Core's logs.
- If the browser process crashes, the WebView is rebuilt (up to 3 times in 2 minutes); if the
  page's renderer crashes, the boot sequence runs again.

## JavaScript bridge

A script injected before every top-level document defines:

```js
window.mimiHost = {
  available: true,
  shell: "winforms-webview2",
  version: "0.1.0",
  info: null,              // the latest host-info message, cached for late listeners
  post(msg) { ... }        // = window.chrome.webview.postMessage(msg)
};
```

Detect the shell with `window.mimiHost?.available`. Page -> host messages (objects with a `type`;
a bare string is accepted too):

| `type` | Extra fields | Effect |
| --- | --- | --- |
| `toggle-fullscreen` | | Toggle full screen. |
| `set-fullscreen` | `value: boolean` | Enter/leave full screen (always answered with `host-info`). |
| `minimize` | | Minimise the window. |
| `exit-to-desktop` | | Hide to the tray (Core keeps running). |
| `quit` | | Quit Mimi (see *Quitting*). |
| `open-logs` | | Open `<root>\logs` in Explorer. |
| `open-folder` | `path: string` | Open a folder inside the Mimi root (relative or absolute); a file is shown selected. Anything outside the root, UNC/device paths and streams are refused. |
| `retry` | | Run the boot sequence again (show the boot screen, restart Core if needed, reload the UI). |
| `get-host-info` | | Ask for a `host-info` message. |

Host -> page messages arrive on `window.chrome.webview.addEventListener('message', e => ...)`:

```js
{ type: "host-info", fullscreen: true, version: "0.1.0", shell: "winforms-webview2", dev: false }
{ type: "host-error", request: "open-folder", message: "Only folders inside the Mimi folder can be opened." }
```

`host-info` is sent after every page load of the UI, on every full-screen change and on
`get-host-info`. Example:

```js
if (window.mimiHost?.available) {
  window.chrome.webview.addEventListener('message', (e) => {
    if (e.data?.type === 'host-info') setFullscreen(e.data.fullscreen);
  });
  mimiHost.post({ type: 'get-host-info' });
  // later: mimiHost.post({ type: 'set-fullscreen', value: false });
}
```

Messages are accepted only from the Core origin and the shell's own boot screen.

## Logs

`<root>\logs\shell.log`: timestamped lines, rolled over to `shell.old.log` past 1 MB. It records
start-up, Core start/stop, bridge messages, blocked navigations (scheme, host and path only - never
query strings), permission decisions and errors.

## Text encoding

`MimiShell.cs` and `splash.html` must stay **pure ASCII**; `build.ps1` refuses to build otherwise.
Write other characters as `…`-style escapes in C# and JavaScript strings, or as HTML entities
(`&hellip;`). The build also passes `/codepage:65001`, but ASCII-only sources can't be garbled by
any code page, editor or compiler setting.

## Troubleshooting

- **"Mimi needs the Microsoft Edge WebView2 Runtime"**: install the Evergreen Runtime (x64) from
  <https://developer.microsoft.com/microsoft-edge/webview2/>. It ships with Windows 11; the
  standalone installer works offline.
- **"Port 7600 is busy"**: another program listens on 7600 and doesn't answer like Core.
- **Boot screen error**: *Open logs folder*, then check `shell.log` and Core's own logs.
- **Build: "MIMI.exe is running"**: quit Mimi from the tray first.

## Design notes

- **Why WinForms + WebView2 + csc?** Everything needed ships with Windows, so anyone can rebuild
  the shell on the device itself, offline, without admin rights.
- **Keys while the page has focus:** the WinForms WebView2 control reports browser accelerator
  keys (F-keys, Alt/Ctrl combinations) through its own `KeyDown` event, not the form's
  `ProcessCmdKey`; the shell handles both.
- **Per-monitor DPI:** the manifest declares PerMonitorV2. WebView2 follows each monitor's scale
  by itself; the shell resizes windowed mode on `WM_DPICHANGED` and keeps full screen matched to
  the monitor when resolution or layout changes.
- **Boot screen state lives in the host.** The page renders whatever state the host pushes
  (`mimiBoot.render(...)`), so the splash-to-error-to-retry transitions happen in place and
  survive a reload of the page.
