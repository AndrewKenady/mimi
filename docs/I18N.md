# Languages

Mimi's interface speaks English, Spanish and French. This page is for anyone changing interface text or adding a language.

## How it works

- **Catalogs.** Text lives in `ui/src/lib/i18n/<lang>/<area>.ts`, one file per area of the app (`chat`, `library`, `settings`…). English (`en/`) is the source. `es/` and `fr/` must match it key for key: each file ends in `satisfies Messages['<area>']`, so `npm run check` fails on a missing, extra or misspelled key.
- **Using a message.** `t('area.key')` in markup or code. Placeholders are `{name}` in the string, filled from `t('area.key', { name })`. Keys are typed, so a typo is a type error.
- **Plurals and grammar** are functions of their params, using `plural()` (which follows each language's rules, so French "0 article" is singular):
  ```ts
  articles: (p: { n: number }) => plural(p.n, { one: '# article', other: '# articles' })
  ```
- **Numbers, dates and lists** use `fmtNumber`, `fmtDate` and `fmtList` from the same module, never `toLocaleString()` without a locale. They follow the interface language, not the browser's.
- **Which language.** Settings → Appearance → Language is per person: Automatic (the browser's language, when Mimi has it), English, Español or Français. Before anyone signs in, the browser's language applies. `<html lang>` follows it, so screen readers switch voices.
- **Core's own words.** Status lines, errors and other text that Core writes arrive in the interface language, because every request carries an `x-mimi-locale` header. Free text that Core passes through (book titles, article text, model output) is never translated.
- **Values from Core with a stable id** (mode ids, collection ids, item nouns such as `articles`) are translated in the interface by id, falling back to Core's English text for anything unknown (a custom mode, a new collection).
- **Answers.** Mimi answers in the language you write in. The library is English, so it searches in English and quotes English sources.

## Style

- **English text stays exactly as it was** when a string moves into a catalog. Tests and screenshots match it.
- **Spanish:** neutral Latin American Spanish, *tú*, no *vosotros*. Use *computadora*, not *ordenador*. Use opening ¿ and ¡.
- **French:** international French, *vous*. Use « guillemets », and put a no-break space (U+00A0) before `: ; ? !` and inside « ».
- **Sentence case** everywhere, as in English. Keep the ellipsis character (…).
- **Length.** Spanish and French run 20–30% longer. Check narrow places (buttons, segmented controls, the nav rail, chips) at 1280×800 and at phone width.
- **Words the user sends to Mimi** (Lens buttons, "Tell me about …" on the Map) are written as the user would say them. French uses *tu* there, as people do with an assistant; everything Mimi says to the user uses *vous*.
- **Names stay names.** Mimi, Lens, Scribe and the Well are not translated, and neither are model names, book titles and place names.

## Adding a language

1. Add it to `LOCALES` in `ui/src/lib/i18n/index.svelte.ts` (its name in its own language) and to `Appearance.language` in `core/mimi/settings.py`.
2. Copy `en/` to the new folder, change each `export default {` to end in `satisfies Messages['<area>']`, and translate.
3. Add Core's strings to `core/mimi/i18n.py`.
4. Add a column to the glossary above.
